# goit-algo-fp

Фінальний проєкт курсу "Алгоритми та структури даних".

## Встановлення та запуск

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python task1.py
python task2.py 10               # або без аргументу, тоді рівень запитується з клавіатури
python task3.py
python task4.py

python task6.py
python task7.py                  # 1 000 000 кидків; python task7.py 100000 для іншої кількості
```

## Завдання 1. Однозв'язний список

- `reverse()` проходить список один раз і розвертає посилання `next` кожного вузла, O(n) часу, O(1) пам'яті.
- `sort()` реалізує сортування злиттям: список ділиться навпіл методом повільного і швидкого вказівника, половини сортуються рекурсивно і зливаються. O(n log n).
- `merge_sorted_lists(a, b)` зливає два відсортовані списки, перепідключаючи наявні вузли, без копіювання. O(n + m).

```
Початковий список:    5 -> 3 -> 8 -> 1 -> 9 -> 2
Після реверсування:   2 -> 9 -> 1 -> 8 -> 3 -> 5
Після сортування:     1 -> 2 -> 3 -> 5 -> 8 -> 9
Об'єднаний: 1 -> 2 -> 3 -> 4 -> 7 -> 8 -> 10 -> 12 -> 15
```

## Завдання 2. Дерево Піфагора

Кожна гілка рекурсивно породжує дві дочірні під кутом ±45° з довжиною, помноженою на √2/2. Рівень рекурсії передається аргументом або вводиться з клавіатури (1-16).

## Завдання 3. Алгоритм Дейкстри

Граф зберігається як списки суміжності. Бінарна купа (`heapq`) щоразу видає найближчу необроблену вершину за O(log V), загальна складність O((V + E) log V). Окрім відстаней, алгоритм відновлює самі шляхи.

```
Найкоротші шляхи від вершини A:
  до A:   0   шлях: A
  до B:   4   шлях: A -> B
  до C:   2   шлях: A -> C
  до D:   9   шлях: A -> C -> E -> D
  до E:   5   шлях: A -> C -> E
  до F:  13   шлях: A -> C -> E -> F
```

## Завдання 4. Візуалізація бінарної купи

Функція `heap_to_tree` перетворює масив купи на дерево з вузлів `Node`: нащадки елемента з індексом `i` мають індекси `2i+1` і `2i+2`. Далі дерево малюється наданою функцією `draw_tree`. Приклад показує min-купу та max-купу.

## Завдання 5. Візуалізація обходів дерева

Обидва обходи ітеративні, без рекурсії:
- **DFS** (прямий обхід) використовує стек; правий нащадок кладеться першим, щоб лівий оброблявся раніше.
- **BFS** використовує чергу `collections.deque`.

Кожен вузол отримує унікальний колір у форматі `#RRGGBB`, який плавно змінюється від темного (`#0B1F3A`, перший відвіданий) до світлого (`#CFE8FF`, останній). Режим `--steps` зафарбовує вузли покроково.

![Обходи DFS і BFS](images/task5_traversals.png)

## Завдання 6. Жадібний алгоритм і динамічне програмування

- `greedy_algorithm` сортує страви за співвідношенням калорій до вартості і бере їх, доки дозволяє бюджет. O(n log n).
- `dynamic_programming` розв'язує задачу рюкзака 0/1 таблицею `dp[i][b]` і відновлює набір страв. O(n · budget).

```
Бюджет: 100
  Жадібний алгоритм:       cola, potato, pepsi, hot-dog
                           вартість: 80, калорії: 870
  Динамічне програмування: pizza, pepsi, cola, potato
                           вартість: 100, калорії: 970
```

При бюджеті 100 жадібний алгоритм обирає hot-dog за вигідним співвідношенням і лишає 20 невикористаних одиниць, а динамічне програмування бере pizza і використовує весь бюджет, отримуючи на 100 калорій більше. Це наочно показує, що жадібний підхід швидкий, але не гарантує оптимального результату. При бюджетах 40 і 120 обидва підходи дають однаковий результат.

## Завдання 7. Метод Монте-Карло

Програма кидає два кубики 1 000 000 разів (`seed=42` для відтворюваності), рахує частоту кожної суми від 2 до 12 і порівнює її з аналітичною імовірністю `(6 - |s - 7|) / 36`.

![Монте-Карло](images/task7_monte_carlo.png)

### Результати

| Сума | Монте-Карло | Аналітично | Різниця |
|:---:|:---:|:---:|:---:|
| 2 | 2.81% | 2.78% (1/36) | +0.029% |
| 3 | 5.53% | 5.56% (2/36) | -0.022% |
| 4 | 8.32% | 8.33% (3/36) | -0.017% |
| 5 | 11.10% | 11.11% (4/36) | -0.011% |
| 6 | 13.88% | 13.89% (5/36) | -0.005% |
| 7 | 16.63% | 16.67% (6/36) | -0.037% |
| 8 | 13.93% | 13.89% (5/36) | +0.043% |
| 9 | 11.15% | 11.11% (4/36) | +0.036% |
| 10 | 8.29% | 8.33% (3/36) | -0.042% |
| 11 | 5.59% | 5.56% (2/36) | +0.030% |
| 12 | 2.77% | 2.78% (1/36) | -0.005% |

### Залежність точності від кількості кидків

| Кількість кидків | Максимальне відхилення від аналітичного значення |
|---:|---:|
| 1 000 | 1.489 в. п. |
| 10 000 | 0.373 в. п. |
| 100 000 | 0.211 в. п. |
| 1 000 000 | 0.043 в. п. |

### Висновки

1. **Розрахунки правильні.** При 1 000 000 кидків імовірності, отримані методом Монте-Карло, збігаються з аналітичними до сотих відсотка: максимальне відхилення становить лише 0.043 відсоткового пункту (сума 8).
2. **Форма розподілу відтворена повністю.** Симуляція дає симетричний "трикутний" розподіл з максимумом на сумі 7 (≈16.67%, бо 7 можна отримати шістьма комбінаціями) і мінімумами на 2 та 12 (≈2.78%, по одній комбінації).
3. **Відхилення мають випадковий характер.** Різниці мають різні знаки і не утворюють систематичного зсуву, тобто це статистичний шум, а не помилка в моделі.
4. **Точність зростає з кількістю випробувань.** Похибка методу зменшується приблизно пропорційно 1/√N: при 1 000 кидків відхилення сягає майже 1.5 в. п., а при мільйоні падає до сотих. Тому для надійної оцінки потрібна велика кількість випробувань.

Отже, метод Монте-Карло дає коректне наближення до теоретичних імовірностей, і що більше симуляцій, то ближчий результат до аналітичного розрахунку.
